# 2026-10-14｜二元线性码：小证书排除局部改动

## 结论

今天转入二元线性纠错码研究，并完成两轮 Claude 讨论及分开编写的整数核查。复现了已知的 [64,11,26] 码；没有构造距离27的新码，也没有证明它不存在。

对本次保存的11×64生成矩阵，已经用可逐项检查的证书排除 **任意替换至多4个生成矩阵列** 达到距离27的可能。另一个仅含3个码字的证书证明：任何距离至少27的11维码，与本基线的交空间维数至多9。这些都是针对本基线的局部限制，不是整个码空间的上界，也不声明原创性。

Grassl的原始参数页在本次检索中仍显示下界26、上界27，来源及检索时效见 [SOURCES.md](SOURCES.md)。纠错码与通信、存储可靠性有关；若同长度和维数下距离由26升到27，最坏情形唯一纠错保证会从12位增至13位。本次未实现这一步，也未验证这个低码率参数的实际部署用途。

## 可检查结果

- 两个不同实现复现同一个已知构造，核对全部2,047个非零码字及生成矩阵秩11。
- 完整重量分布（含零字）：0:1，26:234，28:259，30:420，32:396，34:186，36:261，38:216，40:75。
- 234个最小重量码字的支撑覆盖全部64个单坐标、2,016个坐标对和41,664个三元组。因此这些位置的任何新列值都不可能提高距离。
- 635,376个四元组中，634,824个被单个最小码字支撑覆盖，552个未覆盖。首个未覆盖四元组为{1,4,32,35}（1起算）。所以“支撑覆盖障碍”的最小失效大小恰为4，不能由此推断可成功修改4列。
- 对余下552个四元组，各有一个三最小码字XOR为零的证书。489份证书在删去4列上总重6，63份总重8。它们把全部余下情况也排除。
- 消息11、32、43产生三个重26码字且XOR为零，构成超平面子码的简单障碍。

## 四列证书的理由

任取三个重26码字x、y、z且x+y+z=0。改动4个生成矩阵列后，每个新坐标在这三个码字上的取值只能是000、011、101、110，总贡献至多2。四个新坐标总贡献至多8。

若旧四坐标在三个字上的总重至少6，则三个新字的总重至多78−6+8=80；若它们都重至少27，总重却至少81，矛盾。每个字未改动部分至少有22个1，故不会因秩下降变成零字。这不是逐个枚举2^44新列配置，而是一个覆盖所有配置的整数证书。

独立代码、证书、矩阵、全重量分布及核查日志在 [independent/](independent/)。该目录的README和各证明文件说明具体范围。

## 研究过程与勘误

1. `01_prompt.txt`、`02_claude_reply_original.txt`：精确Collatz叶过滤条件；已知纠错码重建及列替换障碍。
2. `03_prompt.txt`、`04_claude_reply_original.txt`：审查超平面论证，修正更大列替换时遗漏的重量约束及浮点核查的类型混淆。
3. `claude_codes_baseline_audit_original.py`及rerun日志：Claude代码的实际重跑，覆盖33种缩短位置类型；这与另写实现的核查分开标注。
4. `exact_leaf_reference.py`及结果JSON：新写任意精度整数小函数，7,020个二分/线性对照、827个真实头段必要条件检查。没有重新遍历Collatz逆树。

**历史Collatz C程序仍未全范围认证。** 精确数学条件和新参考函数不等于已经修补生产C；Claude的浮点sanity脚本使用Python double，不是历史C long double。详见 [ERRATA.md](ERRATA.md)。原始错误保留。

## 复现

在本目录运行：

```sh
python3 exact_leaf_reference.py
python3 claude_codes_baseline_audit_original.py
cd independent
python3 check_certificates.py
python3 coverage_extension_check.py
```

四列强化的检查命令见 `independent/README.md`。检查器读取已保存证书，不需要网络、随机数、MAGMA或优化求解器。主生成器可重新生成文件；含耗时的日志可能变化，重新生成后要使用重新生成的哈希表。

`claude_exact_threshold_original.py`主程序另外依赖历史的`paradox_cert_J46.json`和`paradox_cert_J58.json`；本增量包不重复这两个旧输入，也不把这个入口写成独立可运行。新参考函数不需要这些依赖。

## 预算与停止

整体上限为30CPU分钟，并非必须耗尽。各新局部实验只有约0.02–0.3CPU秒；Claude编码审计的本地重跑约1.3秒。详细时间与检查器耗时以实际日志为准。对新列取值的巨大穷举和启发式搜索均未启动，因为证书已经排除原定小邻域。研究停在半径4；未扩大到5列，没有新Collatz大扫描。

下一次必须先提出能越过已证障碍的结构性方向，再冻结具体模型和预算。不能把“多改一列、再多跑一点”当作自动继续的理由。
