# 逐项可判定，能否回答整个无限问题？
*HoTT · early exploration*

[阅读索引](../INDEX.md) · [历史草案](../history/2026-10-08/claude_research_note_20261008.md)

## 问题

对一个类型 C，令 P_C(n) 表示“C 处在指定的第 n+2 个 h-level”。如果每个 n 都有局部判定器，能否总是给出以下两种答案之一？

- 一个 n 与 P_C(n) 的证明；
- 对所有 n 的否定证明。

找到正例时，逐项搜索可以停止。一直没有找到正例时，一段有限的搜索记录并不包含全局否定。讨论由此分成局部查询、直接输入全局证书，以及加入额外逻辑原则后能构造的函数。

## 可以清楚说明的部分

考虑一个确定性 oracle 算法，只能逐点读取序列，且相同的查询答案会产生相同的停机轨迹与输出。先在全假序列上运行它。

若有限查询后它声称找到了真值，答案已经错误。若它声称所有位置都假，则把最后一次查询位置之后的序列改为真：已读答案不变，算法输出也不变，全局否定却变成错误。这个对抗构造只使用该次运行的有限查询集，不要求统一时间上界。

这个纸笔论证属于**明确的有限确定性查询模型**。它没有处理随机算法，也没有排除输入已经携带全局证书的函数，更没有直接给出类型论内部闭项不存在的定理。有限 Python 演示用于检查模型与分类，不能替代这些区别。

原草案还讨论了 LPO、LEM 与全局回答的关系。其状态需要分开看：

| 层次 | 存档状态 |
|---|---|
| 有限 oracle 的单轨迹对抗论证 | 在所述模型下的纸笔论证 |
| LPO 到带局部 judge 的全局回答；LEM 到无需局部 judge 的回答 | 纸笔推导，库接口及层级需核对 |
| 从全局回答反推 LPO | 依赖编码引理 E 与尚待闭合的库条件 |
| 新增 Agda / Lean 形式化 | 没有取得编译通过的证据 |

“不可计算”“某模型不成立”“类型论中的逻辑独立”需要不同的证据，不能由同一段算法直觉一起得出。

## 研究评注

这次探索最有价值的修订，是把输入规格还给问题本身。一个局部 judge 和一份全局证书提供的信息不同；若在推导中把它们交换，再精细的证明也会回答另一个问题。

因此，推进应先检查一个有准确类型的引理，而不是继续加重结论。编码 E、宇宙层级和 retract 接口一旦含糊，算法模型中的正确论证也不能替它们补证。当前笔记以草案的证据状态保留，不承担 HoTT 不一致性或逻辑独立性结论。

## 下一步

在固定的库版本下，先形式化最小见证提取：当每个 P(n) 是命题且可判定时，从截断的存在陈述提取一个带证明的最小见证。明确其宇宙层级、命题性与截断消去接口，再考虑编码 E 的连接。内核编译通过，才是这一步完成的标准。
